# R40, R42–R44 — technická příprava přechodu

Implementace `club_cutover_admin.php` pro systémového správce. Nepovoluje produkční import, zapnutí integrace, přesměrování domény, obnovu ani zrušení služby.

## Funkční rozsah

- Verzovaný registr zdrojů a historie, přesně vymezených agend s jediným navrženým zapisujícím systémem, starých/cílových URL, soukromých podkladů, integrací a jejich ručního zastoupení, přejímacích scénářů a konkrétních migračních dávek.
- Vlastník, zdroj důkazu, důvod a nové verze zachovávají historii. Souběžný starý formulář nepřepíše aktuální registr.
- URL nesmí obsahovat přístupové parametry ani credentials. Původní i cílový host odpovídají deklarovanému zdroji/cíli. Mapa není aktivní redirect; callback a soukromý dokument vyžadují samostatné posouzení.
- Přílohy se ověřují přes konkrétní kanonický záznam a skutečný soubor uvnitř soukromého úložiště. Očekávaný hash bez existujícího souboru a shody s kanonickým hashem nikdy nezíská stav ověřených bajtů. Ověření role/čitelnosti je samostatný scénář.
- Kontrolní snímek čte všechny tabulky explicitního zálohovacího vlastnictví kromě čtyř vlastních tabulek přípravy: nyní 325 položek katalogu. Skutečná DB obsahuje 326 tabulek; čtyři vlastní tabulky přechodových metadat se nesnímají, chybějící katalogové položky zůstávají výslovně označené. Zahrnuje peníze i ještě nepřevzaté provider události, fronty, rodiny, účasti, sklad, objednávky a docházku. Ukládá skutečné počty, součty, hash schématu a každého řádku, nikoli osobní obsah. Binární hodnoty mají jednoznačný bajtový otisk; duplicitní řádky bez PK se neslévají. Chybějící tabulka nebo více než 100 000 řádků znamená neúplné ověření.
- Snímek uchovává skutečný lokální Git HEAD a otisky pracovních PHP souborů včetně migrací. Vynechává vendor, node_modules, output, tmp, .codex-tmp, konfigurační soubory a symbolické odkazy. Nejde o tvrzení čistého checkoutu ani důkaz produkční verze.
- Náhled G0–G6 porovnává zdokumentovaný základ s aktuální DB, registry a kódem. Neměnná uložená kontrola zachová i seznam přidaných, změněných a odstraněných záznamů. Nová platba po snímku vyžaduje zachování nových operací; neexistuje tlačítko k přepsání databáze starou zálohou.

## Ověření

- 9 integračních testů / 71 assertions PASS: neměnnost, konflikty verzí, skutečná delta, chybějící tabulky, binary/no-PK multisety, změna schématu, role, přílohy a vlastnictví URL.
- 26 skutečných HTTP scénářů PASS: role a CSRF, verze registru, bezpečné adresy, snímek 325 katalogových položek, skutečný nový syntetický peněžní pohyb, uchovaný rozdíl, nezměněný původní snímek, zákaz falešné autorizace a odebraná role.
- MariaDB race: 3 kontroly PASS. Oba workery byly před uvolněním řádku prokazatelně v `LOCK WAIT`; uspěla přesně jedna verze, druhá dostala srozumitelné odmítnutí.

## Odložené provozní rozhodnutí

Všechny brány zůstávají `production_authorized=false`, `human_acceptance=unknown`. Technický náhled nemůže potvrdit skutečnou přejímku vlastníkem agendy. D13–D16 zahrnují skutečný pilot, konkrétní produkční přechod, první přijaté účetní období a pozdější odstavení starých služeb. Změny těchto stavů nejsou v UI odemykatelným checkboxem. Textově zapsané důkazy nenahrazují skutečnou obnovu, fyzickou inventuru či kontrolu externího systému.

Snímky jsou důkaz porovnání, nikoli obnovitelná záloha. Před skutečným přechodem zbývá ověřit kompletní DB/souborové sady, klíče, obsluhu a dobu obnovy v autorizovaném rozsahu.
